## ADDED Requirements

### Requirement: 用户可只刷新当前仓库的本地展示
系统 MUST 在提交工具栏提供“刷新”操作，重新读取当前仓库的分支、标签、储藏、工作区状态、冲突/操作状态、提交列表和当前选中 diff，且不执行远程网络操作或更改仓库内容。

#### Scenario: 刷新外部工具改动
- **WHEN** 用户在 VS Code 等外部工具修改提交、分支或工作区后点击“刷新”
- **THEN** 系统重新读取当前仓库的本地状态和提交列表，并更新当前选中 diff
- **AND** 系统不执行 Fetch 或其他远程网络请求

#### Scenario: 已选提交在刷新后不可读取
- **WHEN** 刷新期间当前选中的提交已不存在或无法读取
- **THEN** 系统清除过期提交选择并切换到工作区视图

### Requirement: 用户可单独获取远程引用
系统 MUST 在提交工具栏提供“获取远程”操作，并通过独立的 Tauri `git_fetch(path)` 命令运行 Git Fetch。该操作 MUST 只更新远程引用，不合并提交、不切换分支且不改动工作区；结束后系统 MUST 重新读取本地展示状态。

#### Scenario: Fetch 成功
- **WHEN** 用户点击“获取远程”且远程 Fetch 成功
- **THEN** 系统更新远程跟踪引用并刷新分支、提交列表和当前仓库展示
- **AND** 当前分支、提交和工作区内容不因该操作而改变

#### Scenario: Fetch 失败
- **WHEN** Fetch 因无远程配置或网络错误而失败
- **THEN** 系统显示 Git 错误、结束操作进度、刷新本地展示，并允许用户再次尝试

#### Scenario: Fetch 超时
- **WHEN** Fetch 执行超过 30 秒
- **THEN** 系统终止 Git 子进程、显示超时错误、刷新本地展示并结束操作进度
- **AND** 用户可以再次执行 Fetch

### Requirement: 刷新与 Fetch 操作显示明确进度
系统 MUST 在任一操作执行期间显示相应进度，并禁用刷新与 Fetch 按钮以阻止重复操作。

#### Scenario: 操作执行中
- **WHEN** 刷新或 Fetch 正在执行
- **THEN** 对应进度文案可见且两个入口均不可重复触发
- **AND** 操作结束后按钮恢复可用
