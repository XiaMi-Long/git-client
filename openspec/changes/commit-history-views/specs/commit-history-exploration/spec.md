## ADDED Requirements

### Requirement: 用户可在统一入口切换提交历史视图
系统 MUST 在经典列表和作者泳道之外提供分支拓扑、文件历史、版本标签和活动热力图视图，并在经典列表中提供日期分组。视图选择器 MUST 显示当前视图名称及各视图用途，避免将作者泳道和分支拓扑混淆。

#### Scenario: 切换提交历史视图
- **WHEN** 用户打开视图选择器并选择另一种视图
- **THEN** 历史区切换到所选视图，选择器关闭，既有提交选择和全局分支范围保持不变

#### Scenario: 使用键盘切换视图
- **WHEN** 用户聚焦视图选择器并使用方向键、Home/End、Enter 或 Escape
- **THEN** 焦点按菜单顺序移动，Escape 收起菜单并返回触发按钮，Tab 离开菜单时菜单自动收起

#### Scenario: 兼容旧视图设置
- **WHEN** 应用读取只包含旧 `commitListMode` 的设置
- **THEN** `classic` 或 `swimlane` 被映射为对应视图并继续显示

#### Scenario: 切换仓库
- **WHEN** 用户切换到另一个仓库
- **THEN** 当前视图保持，旧仓库的路径、标签范围、日期选择、提交选择和 diff 被清除，视图加载新仓库数据并回到顶部

### Requirement: 历史视图保持提交选择和浏览状态
系统 MUST 让各提交视图通过统一提交选择展示右侧文件和 diff，并在视图切换时保留该视图的滚动位置及本地筛选。历史查询 MUST 限定一个明确的 Git 仓库；除文件历史外，该仓库为当前仓库，文件历史以绝对路径所属仓库为准。文件、拓扑和活动视图 MUST 遵循当前/所有分支范围；文件历史查询外部仓库时，“当前分支”指目标仓库的 HEAD。版本视图 MUST 使用显式标签范围，过期异步响应 MUST 被丢弃。

#### Scenario: 在不同视图查看同一提交
- **WHEN** 用户在任意提交视图选择一条提交
- **THEN** 右侧现有文件列表与 diff 展示该提交的内容

#### Scenario: 在外部仓库查看文件历史提交
- **WHEN** 用户从当前仓库以外的 Git 仓库文件历史中选择提交
- **THEN** 右侧文件列表和 diff 使用该提交所属的目标仓库读取，外部仓库提交保持只读

#### Scenario: 返回已浏览视图
- **WHEN** 用户切换到另一视图后再返回
- **THEN** 原视图的滚动位置和本地筛选恢复

#### Scenario: 旧查询晚于新仓库返回
- **WHEN** 用户切换仓库或查询条件后旧请求才完成
- **THEN** 旧结果不会覆盖当前仓库或当前筛选的数据

### Requirement: 经典列表支持按日期分组
系统 MUST 在经典提交列表中默认启用日期分组，以应用本地时区的提交时间（committer date）显示分组，并允许用户手动关闭；系统 MUST 保持现有提交搜索、分页、虚拟滚动和选择能力。

#### Scenario: 默认启用日期分组
- **WHEN** 用户首次打开经典提交列表
- **THEN** 列表按日期分组，且视图菜单中的“列表按日期分组”显示为已启用

#### Scenario: 浏览日期分组
- **WHEN** 用户启用日期分组
- **THEN** 同一日的提交归入同一日期区块，跨分页时日期顺序和提交顺序保持正确

### Requirement: 分支拓扑视图展示真实提交关系
系统 MUST 提供按拓扑顺序展示的提交图，使用真实父提交关系连接节点，并支持当前/所有分支范围和分页。

#### Scenario: 浏览分支与合并关系
- **WHEN** 用户打开分支拓扑视图
- **THEN** 提交节点根据父提交关系显示分支线和合并线，节点可选中以查看右侧 diff

#### Scenario: 父提交尚未加载
- **WHEN** 当前页的提交父节点位于尚未加载的历史页
- **THEN** 图中显示延伸线而不伪造父节点，继续加载后连接到真实父节点

### Requirement: 用户可查看文件或目录的历史
系统 MUST 允许用户输入任意 Git 仓库内的绝对文件或目录路径，并展示该路径的提交历史；路径查询 MUST 遵循分支范围、文本搜索和分页。系统 MUST 从输入路径定位 Git 仓库根目录，再将路径转换为该仓库的相对 Git pathspec。绝对路径不属于任何 Git 仓库时，系统 MUST 显示可理解的错误。

#### Scenario: 查询文件历史
- **WHEN** 用户提交一个文件或目录路径
- **THEN** 历史列表只显示影响该路径的提交，选择提交仍可查看右侧 diff

#### Scenario: 输入任意仓库内的绝对路径
- **WHEN** 用户输入任意 Git 仓库下的 Windows 或 POSIX 绝对路径
- **THEN** 系统定位路径所属的仓库，将它转换为目标仓库相对路径查询 Git 历史，并在输入框保留规范化后的绝对路径

#### Scenario: 输入相对路径或非 Git 路径
- **WHEN** 用户提交相对路径，或提交未处于任何 Git 仓库中的绝对路径
- **THEN** 系统显示路径格式或仓库定位错误，不发起 Git 历史查询

#### Scenario: 从提交文件快捷进入历史
- **WHEN** 用户从右侧文件列表选择“查看文件历史”
- **THEN** 文件历史视图打开并以该文件路径作为查询条件

### Requirement: 用户可按版本标签浏览提交范围
系统 MUST 展示仓库标签的时间线和目标提交，并允许用户浏览一个目标标签或选择基准与目标标签查看其间提交。

#### Scenario: 浏览目标标签
- **WHEN** 用户选择一个标签且未指定基准标签
- **THEN** 系统展示从该标签可达的提交历史

#### Scenario: 浏览两个标签之间的提交
- **WHEN** 用户指定基准标签和目标标签
- **THEN** 系统展示 `基准..目标` 的提交范围，且选择提交后可查看右侧 diff

#### Scenario: 轻量标签和附注标签
- **WHEN** 版本时间线包含轻量标签或附注标签
- **THEN** 每个标签都指向其实际提交，并显示可用的标签创建时间或目标提交时间

### Requirement: 用户可查看并钻取近期提交活动
系统 MUST 提供最近 180 天按日聚合且铺满历史区域可用宽度的提交活动热力图，同时保持适中的方格尺寸；热力图遵循当前/所有分支范围，并允许按日期查看提交明细。热力图和分支拓扑中的提交文字 MUST 与普通提交列表保持一致的字号层级。

#### Scenario: 展示提交活动热力图
- **WHEN** 用户打开活动视图
- **THEN** 系统展示最近 180 天的每日提交数量，包括零提交日期

#### Scenario: 查看某天的提交
- **WHEN** 用户选择热力图中的日期
- **THEN** 系统列出该日的提交，保留文本搜索条件，且每条提交可打开右侧 diff

#### Scenario: 仓库近期没有提交
- **WHEN** 最近 180 天没有符合分支范围的提交
- **THEN** 热力图仍展示完整日期区间并显示无活动状态

#### Scenario: 宽屏浏览提交活动
- **WHEN** 用户在宽屏窗口打开提交活动视图
- **THEN** 日期热力图按可用宽度铺展且日期格保持适中大小，提交活动文字清晰度与普通历史列表一致

### Requirement: 历史视图控件遵循应用样式
文件历史的查询按钮和设置中的历史视图选择控件 MUST 使用应用提供的颜色、边框、焦点和悬停样式，不显示浏览器或操作系统原生控件外观。

#### Scenario: 操作历史视图控件
- **WHEN** 用户查看文件历史或打开设置中的历史视图选择菜单
- **THEN** 控件使用应用主题样式，并支持键盘聚焦和操作
