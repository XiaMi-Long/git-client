## Context

当前历史区有经典提交列表和按作者分列的泳道图，共用 `commitStore.commits`。列表支持分页和搜索，提交详情与文件 diff 位于右侧。提交数据已有父提交哈希、refs、作者和日期；仓库状态已读取标签。后端日志查询尚不支持路径、日期区间或拓扑排序，活动趋势也没有聚合接口。

视图数量会从两个增加到六个，因此切换入口、视图状态和提交选择的一致性是本次主要设计约束。保留现有 Git 操作栏、右侧 diff 面板和“当前分支/所有分支”语义。

## Goals / Non-Goals

**Goals:**

- 提供列表、作者泳道、分支拓扑、文件历史、版本标签、活动热力图六种互补浏览方式，并在经典列表中增加日期分组。
- 让提交选择和提交详情在各视图间保持连续；除版本视图使用显式标签范围外，其余视图沿用当前/所有分支范围；切换视图时保留各自筛选、滚动位置和最近浏览状态。
- 对超出视口的历史使用分页或固定时间范围；异步响应不得覆盖切换仓库或筛选后的新状态。
- 通过现有 Tauri Git 执行器查询历史，不新增依赖、不改写仓库。

**Non-Goals:**

- 不提供提交改写、分支操作、版本比较 diff 或远程托管服务活动流。
- 不改变已有作者泳道的列语义和现有提交 diff 工作流。
- 活动视图仅统计最近 180 天的提交数量，不作为完整贡献分析或代码量统计。

## Decisions

### 视图选择与状态连续性

- 把设置中的二态 `commitListMode` 演进为持久化的 `commitHistoryView`，支持 `classic`、`swimlane`、`graph`、`file`、`release`、`activity`。读取旧设置时将 `commitListMode` 映射到前两种，用户已有偏好不会丢失。
- 用一个带当前视图名称的菜单式选择器列出六种视图，并用一行用途说明区分“作者泳道”和“分支拓扑”。鼠标打开时聚焦当前选项；键盘支持方向键、Home/End、Enter 和 Escape。选择后菜单关闭并把焦点交还触发按钮；Tab 离开菜单时收起菜单。原有搜索、分支范围和提交选择不因切换而清空。
- 各视图容器切换显示而非销毁，保留滚动位置和本地筛选；仓库切换时清除路径、标签范围、日期选择等仓库特定状态。请求使用序号或活动仓库校验丢弃过期结果。
- 所有视图的提交行都调用同一 `selectionStore.selectCommit`，继续使用现有右侧文件列表和 diff。文件历史会额外传递目标仓库根路径，让跨仓库选中的提交仍可正确读取详情；外部仓库提交不提供针对当前仓库的 cherry-pick 操作。

### 历史查询与展示

- 扩展 `LogQuery` 的可选条件：路径、拓扑顺序、起始日期和结束日期。路径作为 `--` 后的 pathspec 传给 Git；查询仍保留已有分页、分支范围和文本搜索。
- 分支拓扑模式请求 `--topo-order` 日志并按父哈希计算可见节点连线。边界父提交不在已加载页时绘制为延伸中的连线，不伪造节点；接近底部时继续分页。它是独立的完整主视图，避免恢复被用户移除的窄侧栏小图。
- 文件历史输入任意 Git 仓库内的绝对路径，并可从右侧提交文件列表快捷带入路径；后端向上定位 Git 根目录，前端转换为仓库相对 pathspec。当前仓库的分支范围沿用现有选择，外部仓库使用其 HEAD 或所有分支范围。提交行保持可选中并从目标仓库读取差异。
- 版本视图按标签日期展示标签、目标提交和摘要。用户选择目标标签，可再选择可选的基准标签；有基准时查询 `基准..目标`，无基准时浏览目标标签可达的提交。修正标签读取：附注标签解析到剥离后的提交哈希，轻量标签使用目标提交日期。
- 活动视图用后端聚合的最近 180 天提交日历热力图。点击某天后在热力图下方加载当天提交；当前/所有分支范围继续生效，已有文本搜索保留并应用于当天提交明细。统计和明细都按应用本地时区的 Git committer date 日历日期筛选。
- 经典列表日期分组默认开启，以日期标题分隔提交；用户仍可通过视图菜单关闭，作者泳道维持现有布局。各视图在加载、空数据、查询失败时显示明确状态。

### 活动聚合接口

- 新增 `git_get_commit_activity(path, days, branch, all_branches)`，返回 `{ date, count }[]`。`days` 固定由前端传 180，接口仅返回有提交的日期；视图补齐无提交日期以形成连续热力图。
- 后端运行限定最近天数的 `git log`，只输出提交者 ISO 日期并按日计数；`all_branches` 使用 `--all`，否则用显式分支或 `HEAD`。不返回每个提交的完整详情。

## Risks / Trade-offs

- **拓扑图连线可能因提交顺序或分页边界显得不连续** → 只使用 `--topo-order` 结果和真实父哈希；边界以开放端点表示，已加载更多页后重新计算。
- **大仓库的路径或日期日志仍可能很大** → 文件视图复用 100 条分页；活动查询只读取最近 180 天且只传日期字段。
- **轻量标签没有独立 tagger 时间** → 使用其目标提交的提交者日期作为版本时间，并在界面统一展示该日期。
- **旧版设置字段仍需兼容** → 首次读取优先新字段，其次映射旧 `commitListMode`，随后持久化新字段。
- **模式切换期间异步查询可能返回过期数据** → 每个异步视图请求在仓库或筛选变化时递增请求序号，只接受最新响应。

## Migration Plan

1. 添加兼容旧设置的多视图字段和选择器，再接入新视图组件。
2. 扩展日志查询并注册活动聚合与绝对路径仓库定位命令；文件历史查询和详情可使用路径所属的任意 Git 仓库。
3. 静态检查 OpenSpec 变更与代码差异；不运行 Vue 类型检查、测试或打包命令。

回滚时删除新视图和新命令，并保留读取旧 `commitListMode` 的兼容逻辑，既有设置不丢失。
