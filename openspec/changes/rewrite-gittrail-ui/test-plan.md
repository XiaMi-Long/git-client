# 重写主界面测试与验证计划

## 测试范围、数据与前置条件

- 范围：项目列表/别名/排序、提交列表/搜索/分页、Review、设置、分支、远程、冲突、储藏、cherry-pick、旧入口下线、错误与并发反馈。
- 环境：Windows + Tauri 2 WebView2；使用用户本机真实 Git 仓库（至少一个含多分支、远程、冲突历史、stash 的仓库；无则在可操作仓库中构造）。
- 数据：不写入真实业务仓库的破坏性操作；删除分支/远程分支/储藏使用临时或可恢复数据；不使用真实凭据注入；不保存密码。
- 可执行方式：默认仅代码阅读 + `git diff`；浏览器、构建、类型检查、自动化测试均未获本次授权。
- 外部依赖：系统 Git 可用、仓库路径可读、网络/远程凭据仅在用户实际验证时提供；应用不上传仓库内容。

## 提测准入标准

- 功能闭环：项目、提交、Review、设置、分支、远程、冲突、储藏、cherry-pick 可在真实仓库完成；旧入口不出现。
- 数据正确：分支/提交/diff/储藏/操作状态字段来自后端；项目别名只影响显示。
- 状态完整：加载、空、失败、操作中、成功、冲突、部分完成均有明确反馈。
- 稳定性：连点防重复；切项目/分支丢弃旧响应；弹窗关闭不继续写状态。
- 权限/安全：本地应用无账号权限；不保存凭据；危险操作确认；不执行未授权外部操作。
- 环境：Chrome/Edge/WebView2、分辨率、Console/Network —— **未执行，待用户授权和实际运行**。
- 结论：本轮仅可做静态核对和代码级自检；浏览器/构建/自动化未执行，不写“全部通过”。

## 获准验证方式与限制

- 已获准：代码阅读、`git diff`、静态逻辑检查。
- 未获准：构建、`vue-tsc`/类型检查、启动 dev server、浏览器自动化、安装测试依赖、真实远程写操作。
- 人工验证步骤：由用户在本地 `npm run tauri dev`（或现有开发命令）启动后按 MF/ST 用例执行；任何构建/测试命令需用户明确授权。
- 有原型时开发后的实际 UI 对照需真实运行/截图；未授权时在 verification 中保留“待执行”，不以代码推断替代。
