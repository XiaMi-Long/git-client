# 需求审查与澄清

## 分析依据与需求理解

- 用户目标：把已确认的 GitTrail 新原型实现成真实 Tauri 2 + Vue 3 应用，替换旧 UI，用真实 Git 数据完成日常历史、审查、分支、远程、冲突、储藏和 cherry-pick。
- 业务原型：`prototype/index.html`、`style.css`、`app.js`（2026-11-04，可读，已交互迭代）。
- 现有实现：`src/App.vue` 目前挂 `MainView` 三栏旧 UI；`repo`/`commit`/`selection`/`settings`/`theme` stores 和分支、远程、储藏、diff、日志后端命令已存在；`git_set_upstream`、`git_merge_continue` 缺失。
- 用户已确认：直接替换；允许内部 add/自动 commit；冲突外部编辑器解决；移除压缩挑拣。
- 约束：不做手工暂存/提交 UI；旧泳道/历史视图/工作区/提交框下线；无浏览器/构建/测试授权。

## 已确认范围、假设与可选建议

- 已确认：直接替换旧 UI；旧泳道/历史视图/工作区/提交框下线；允许内部 add/自动 commit；冲突外部编辑器解决；移除压缩挑拣；真实 Git 后端。
- 项目添加已确认（Q8）：保留单个/批量两个入口；批量在系统窗口中多选项目文件夹，沿用现有仓库校验、重复跳过、部分失败继续和保留当前项目的处理。
- 已采用（不改变业务）：新设置页保留旧版设置项（Q5）；补 `git_set_upstream`、`git_merge_continue`（Q7）；项目添加/移除沿用旧版能力。
- 可撤回假设：新建储藏默认全部改动（Q6）。若用户后续要求范围选择，再补 all/staged/unstaged。
- 未采纳建议：暂无。大 diff 虚拟化列为后续优化，不进入本次必做。
