## ADDED Requirements

### Requirement: 项目列表必须使用真实仓库并持久化显示别名与顺序

应用 MUST 从已打开的 Git 仓库加载左侧项目列表，项目切换、添加、移除、拖拽排序和显示别名 MUST 使用真实本地路径；别名 MUST 只影响软件内显示，不得修改仓库目录或 Git 配置。

#### Scenario: 启动恢复上次项目

- **WHEN** 应用启动且 localStorage 中存在有效项目路径
- **THEN** 应用从本地存储一次显示项目行和别名，沿用保存顺序。激活上次项目后优先加载其仓库数据和首屏提交
- **AND** 当前项目准备后，后台逐步补齐其他项目的本地分支和已知待拉取、待推送数量。其他项目的提交、工作区和储藏在激活时加载
- **AND** 校验发现失效路径时，从当前列表跳过该项。上次项目不可用时，按项目栏顺序选择可用仓库
- **AND** 启动期间允许选择其他项目。较早的校验和刷新结果不应覆盖更新的选择或数据

#### Scenario: 拖拽排序并保存

- **WHEN** 用户将一个项目拖到另一项目位置后释放
- **THEN** 项目顺序立即更新并写入本地存储；真实仓库路径保持不变
- **AND** 刷新或重启后顺序保持

#### Scenario: 重命名显示别名

- **WHEN** 用户在项目行右键选择重命名并输入非空名称
- **THEN** 项目列表显示新别名，主头部以别名为主标题，并在旁边以次要样式显示原始目录名；localStorage 保存别名，仓库操作以实际目录路径为准
- **AND** 输入为空时提示并保留原显示名
- **AND** 别名与原始目录名相同时标题只显示一份名称，长名称可截断并通过悬停查看完整内容

#### Scenario: 复制项目绝对路径

- **WHEN** 用户在左侧项目行的右键菜单选择「复制绝对路径」
- **THEN** 应用将该项目的实际仓库目录路径写入系统剪贴板，收起菜单并提示复制结果

#### Scenario: 单个添加项目

- **WHEN** 用户点击单个添加入口，在系统目录窗口中选择一个有效 Git 仓库
- **THEN** 应用将该仓库加入项目列表并持久化；已打开的路径不得重复添加
- **AND** 取消目录选择时保留现有项目和当前激活项目

#### Scenario: 批量添加项目

- **WHEN** 用户点击独立的批量添加入口，在系统目录窗口中多选项目文件夹
- **THEN** 应用逐个校验并添加有效仓库，跳过已打开的路径；单个目录失败不得阻断其余目录
- **AND** 存在成功项目时反馈成功数量和部分失败数量；已有当前项目时保持原项目，无当前项目时激活首个成功项目
- **AND** 目录选择窗口打开失败时展示错误，操作结束后释放两个入口的禁用状态

#### Scenario: 移除当前项目

- **WHEN** 用户移除当前激活项目且仍有其他项目
- **THEN** 应用停止旧仓库监听、切换到下一个项目并刷新；被移除项目不再显示
- **AND** 不删除磁盘目录

### Requirement: 提交列表必须展示真实提交并支持搜索与分页

应用 MUST 通过 `git_get_log` 加载当前仓库提交，展示短哈希、作者、提交主题、refs 和日期分组；搜索 MUST 支持提交信息、作者和哈希；列表 MUST 区分加载中、有数据、无匹配、空仓库和读取失败。

#### Scenario: 加载当前分支提交

- **WHEN** 激活项目的当前分支有提交
- **THEN** 提交按日期倒序分组展示，作者、refs 和 unpushed 标识来自真实数据
- **AND** 未推送提交在原元信息行显示带底色、描边与粗体的「未推送」徽标，配色随界面明暗主题切换
- **AND** 提交时间保持单行并按时间格式分配列宽，过长的时间文字可悬停查看完整内容
- **AND** 滚动到底可加载下一页；无更多数据时停止请求

#### Scenario: 搜索无匹配

- **WHEN** 用户输入不匹配任何提交的关键词
- **THEN** 列表显示“没有匹配的提交”并提供清除筛选入口
- **AND** 不把接口失败显示为空结果

#### Scenario: 读取失败

- **WHEN** 提交日志查询失败
- **THEN** 保留可用的既有数据或显示失败说明，提供重试路径
- **AND** 不伪造成功或空仓库结论

#### Scenario: 切换范围

- **WHEN** 用户切换项目，或在主列表切换当前分支和所有分支的范围
- **THEN** 列表按新范围重新加载；旧请求响应不得覆盖新范围结果
- **AND** 切换项目或分支范围期间，提交区隐藏「正在加载提交…」提示。查询结束后按实际结果展示提交、空态或错误

#### Scenario: 顶栏搜索换行

- **WHEN** 主区宽度不足以在同一行容纳分支操作与搜索
- **THEN** 搜索框换到下一行，与操作区左边缘对齐。同一行放得下时搜索框靠右

#### Scenario: 打开作者快捷选项

- **WHEN** 用户点击或聚焦提交搜索框，且当前有打开的仓库
- **THEN** 搜索框下方列出当前浏览范围内近半年有提交的作者，包含用户本人，以 Git 姓名和邮箱区分同名作者
- **AND** 浮层区分读取中、无作者与读取失败，失败后可重试

#### Scenario: 按作者和关键词筛选提交

- **WHEN** 用户选择一个作者
- **THEN** 浮层收起，搜索框展示可清除的作者标签，提交结果同时匹配作者身份与当前关键词
- **AND** 近半年范围用于生成作者选项。作者筛选覆盖当前分支范围内的历史，清除作者时保留关键词

#### Scenario: 切换作者选项的查询范围

- **WHEN** 用户切换仓库或浏览分支范围
- **THEN** 已展开的浮层收起，重新展开时读取新范围的作者。原范围的请求不得更新新选项
- **AND** 切换仓库时清除关键词及作者条件。切换同仓库的分支范围时，现有筛选条件应用到新范围

#### Scenario: 复制提交信息

- **WHEN** 用户在提交行右键菜单选择「复制提交信息」
- **THEN** 应用将该提交的标题和可选正文写入剪贴板，标题和正文之间保留一个空行
- **AND** 菜单收起并提示复制结果

### Requirement: 提交审查弹窗必须展示真实 diff 并支持键盘操作

点击提交 MUST 打开审查弹窗，通过 `git_get_commit_diff` 读取真实文件差异；MUST 支持文件列表、统一/双栏视图、自动换行、上一个/下一个提交、复制哈希和 Esc 关闭；长文本与长 diff MUST 保持可滚动。

#### Scenario: 查看提交文件

- **WHEN** 用户打开某提交审查
- **THEN** 文件列表与 diff 对应该提交；选择文件后展示对应差异和增删统计
- **AND** 无文件改动时展示明确空说明

#### Scenario: 切换视图与换行

- **WHEN** 用户点击统一、双栏或换行
- **THEN** 当前文件 diff 按选择重新渲染，状态按钮可识别
- **AND** 代码内容可横向或自动换行滚动，不遮挡文件列表

#### Scenario: 键盘关闭与前后提交

- **WHEN** 弹窗打开且焦点在弹窗内，用户按 Esc、`[`、`]`
- **THEN** 分别关闭弹窗、切换上一个/下一个提交；焦点不逃逸到背景

### Requirement: 分支管理必须调用真实 Git 命令并保护当前分支

应用 MUST 展示本地与远程分支，支持检出、新建、重命名、删除、合并到当前分支、从远程创建本地分支和设置上游；当前分支 MUST 禁止直接删除；危险操作 MUST 二次确认；操作失败 MUST 展示 Git 原因。

#### Scenario: 检出分支

- **WHEN** 用户对非当前本地分支执行检出且工作区允许切换
- **THEN** 当前分支更新，提交列表和分支选中态刷新
- **AND** 若工作区阻止切换，应用提示原因并保留原分支

#### Scenario: 新建或重命名分支

- **WHEN** 用户输入合法且不重复的新分支名
- **THEN** 调用真实 Git 创建/重命名并刷新分支列表；新分支可被检出
- **AND** 空名称、空白或重复名称被拦截并保留输入

#### Scenario: 删除分支

- **WHEN** 用户对非当前分支确认删除
- **THEN** 调用 `git_delete_branch` 删除并刷新；取消不执行
- **AND** 当前分支删除入口禁用并说明原因

#### Scenario: 合并发生冲突

- **WHEN** 用户确认合并且 Git 返回冲突
- **THEN** 应用进入冲突状态并展示冲突条；已完成/未完成状态与 Git 一致
- **AND** 无冲突时展示成功结果并刷新提交/分支

#### Scenario: 从远程创建与设置上游

- **WHEN** 用户选择远程分支创建本地分支或为本地分支选择远程上游
- **THEN** 调用真实 Git 创建 tracking/设置上游，刷新分支信息
- **AND** 名称冲突或远程引用失效时提示并保留原状态

### Requirement: 非当前分支使用独立预览弹窗

点击非当前本地分支或远程分支 MUST 打开独立弹窗，以完整引用查询分支历史，支持分页、重试和提交审查。弹窗 MUST 随窗口大小调整并保留边距。主列表的范围、筛选和当前检出的分支 MUST 保持。打开预览 MUST 只读本地数据。检出仍由分支操作菜单发起。

#### Scenario: 查看并同步本地分支

- **WHEN** 用户在检出的 A 分支中打开本地 B 的预览
- **THEN** 弹窗显示 B 的提交、其实际远程上游及已知的待拉取和待推送数量，缺少上游或上游引用时说明原因
- **AND** 用户可手动获取该上游。拉取只快进更新 B，分叉或 B 已在某工作区检出时提示原因。推送按 B 的配置执行普通推送，支持与本地不同名的上游分支
- **AND** 操作期间显示进度并防止重复执行。结束后重新读取原仓库和仍打开的预览，主列表保留原查询，切换项目时关闭预览

#### Scenario: 筛选本地分支提交

- **WHEN** 用户在本地分支预览点击搜索框并选择作者或输入关键词
- **THEN** 作者候选来自该分支最近半年的提交。历史按所选作者与关键词过滤，并允许单独清除条件
- **AND** 筛选查询覆盖该分支的历史，独立于主列表。筛选后无匹配时提供清除筛选入口

#### Scenario: 查看远程分支

- **WHEN** 用户点击远程分支
- **THEN** 弹窗展示该远程分支在本地的历史和提交差异，只在本地分支预览提供手动同步

### Requirement: 分支星标按项目保存在本机

应用 MUST 允许通过分支的「⋯」菜单为本地或远程分支设置和取消星标。标记 MUST 按仓库路径和完整分支引用分别保存，保留分组及列表顺序。设置星标只改变应用内展示。

#### Scenario: 标记和取消标记

- **WHEN** 用户在本地或远程分支菜单选择「标记分支」或「取消标记」
- **THEN** 操作菜单收起，分支列表保留，对应分支名称旁的星标即时显示或移除

#### Scenario: 切换项目或重启后恢复标记

- **WHEN** 用户切换项目或重新启动应用
- **THEN** 各项目只显示自己保存的星标，本地和远程分支分别匹配，旧布局缺少标记时按未标记处理

### Requirement: 远程同步必须展示真实结果并避免重复执行

应用 MUST 支持 fetch、pull、push、删除远程分支和设置当前分支上游；操作进行中 MUST 防止重复触发；成功或失败 MUST 以真实 Git 结果为准，失败不得清空已有提交/分支数据。

当前检出分支的拉取与推送按钮及 ahead/behind 数量 MUST 常驻顶栏。点击后 MUST 立即显示进行中状态，菜单收起后仍可见。获取远程引用 MUST 由用户手动触发。

#### Scenario: 不打开菜单即可识别并操作

- **WHEN** 当前分支相对上游存在待拉取或待推送提交
- **THEN** 顶栏直接显示拉取/推送按钮及对应数量，按钮提示明确实际检出的目标分支
- **AND** 执行期间按钮显示转圈和操作文案，并与其他 Git 写操作互斥；结果刷新后释放进行中状态

#### Scenario: 手动获取与切换隔离

- **WHEN** 用户点击「获取远程」或错误提示中的「重新检查」
- **THEN** 获取远程引用并刷新该项目的分支状态
- **AND** 操作期间切换项目时，原请求只更新原项目，反馈注明原操作对象

#### Scenario: 启动或切换时等待手动获取

- **WHEN** 应用启动、切换项目或窗口回到前台，且当前没有用户发起的远程操作
- **THEN** 远程获取保持空闲，显示当前项目已有的本地分支信息

#### Scenario: 更多菜单展示长上游名称

- **WHEN** 用户打开更多菜单，且当前分支的上游名称较长
- **THEN** 操作文字保持单行，上游名称超出提示列时用省略号显示，悬停可查看全名

#### Scenario: 尚未检查或检查失败

- **WHEN** 当前分支未配置上游、尚未成功检查远程或检查失败
- **THEN** 分别显示未设置上游、尚未检查或真实失败原因，不将零数量直接判定为已同步
- **AND** 失败后保留可用数据，用户可手动重新检查

#### Scenario: 拉取成功

- **WHEN** 用户对当前分支执行 pull 且无冲突
- **THEN** 分支/状态/提交刷新，提示成功
- **AND** 不重复发送同一操作

#### Scenario: 拉取冲突

- **WHEN** pull 返回冲突
- **THEN** 应用进入冲突状态并提供处理入口
- **AND** 不把冲突显示为成功

#### Scenario: 无上游推送

- **WHEN** 当前分支没有上游且用户执行 push
- **THEN** 应用提示缺失上游并提供设置上游入口
- **AND** 不虚假提示推送成功

#### Scenario: 删除远程分支

- **WHEN** 用户确认删除远程分支
- **THEN** 调用真实删除命令并刷新远程分支列表
- **AND** 失败时保留原远程分支并说明原因

### Requirement: 冲突处理必须允许外部编辑并在应用内标记与继续

发生 merge、pull 或 cherry-pick 冲突时，应用 MUST 展示操作类型、冲突文件和已解决状态；MUST 提供用系统默认程序打开冲突文件、标记已解决、检查残留冲突标记、继续和中止；继续 MUST 按操作类型调用对应 continue 命令。

#### Scenario: 标记并继续

- **WHEN** 用户已在外部编辑器解决冲突并逐个标记已解决
- **THEN** 继续前检查残留冲突标记；无残留时调用对应 merge/cherry-pick continue
- **AND** 成功后离开冲突状态并刷新；失败保留冲突状态和原因

#### Scenario: 残留冲突标记

- **WHEN** 冲突文件中仍存在冲突标记
- **THEN** 应用拦截继续，列出相关文件并提示先完成解决
- **AND** 不执行提交/继续

#### Scenario: 中止冲突

- **WHEN** 用户确认中止当前冲突操作
- **THEN** 调用真实 abort 命令，回到 normal 并刷新
- **AND** 已完成的独立 cherry-pick 不受无关回滚影响

#### Scenario: 外部编辑器打开失败

- **WHEN** 系统无法打开冲突文件
- **THEN** 提示失败原因和文件路径，保留标记/继续/中止入口

### Requirement: 储藏管理必须使用真实 stash 数据

应用 MUST 从 `git_list_stashes` 展示真实储藏，支持新建、应用、查看和删除；新建默认收全部改动（含未跟踪），应用/删除 MUST 以真实 Git 结果刷新列表。

#### Scenario: 新建与应用储藏

- **WHEN** 用户输入非空名称并确认新建，随后应用某条储藏
- **THEN** 新储藏真实写入并出现在列表；应用后刷新工作区/状态与储藏
- **AND** 名称为空或 Git 失败时提示，不新增假条目

#### Scenario: 删除储藏

- **WHEN** 用户确认删除某条储藏
- **THEN** 调用 drop 并从列表移除；取消不执行
- **AND** 失败时保留原条目

### Requirement: Cherry-pick 必须可用且不提供压缩挑拣

提交右键菜单 MUST 提供 Cherry-pick 到当前分支；冲突 MUST 进入统一冲突处理；MUST NOT 提供压缩挑拣（Squash Pick）入口。

#### Scenario: 挑选成功

- **WHEN** 用户对某提交执行 Cherry-pick 且无冲突
- **THEN** 调用真实命令，刷新提交/分支并提示成功
- **AND** 菜单不出现压缩挑拣

#### Scenario: 挑选冲突

- **WHEN** Cherry-pick 返回冲突
- **THEN** 进入冲突状态，可继续/中止
- **AND** 不把冲突结果当成功

### Requirement: 设置页必须保留现有设置并支持主题与密度

设置页 MUST 支持 system/light/dark 主题与 comfortable/compact 密度并持久化；MUST 保留旧版 Git 路径、默认打开目录、远程分支保护、储藏名模板和时间格式等设置能力；旧设置弹窗不得继续作为唯一入口。

设置页 MUST 提供可独立选择并保存的代码对比主题。

#### Scenario: 切换主题

- **WHEN** 用户选择 system、light 或 dark
- **THEN** 页面立即应用对应主题并持久化；system 跟随操作系统
- **AND** 重新启动后保持选择

#### Scenario: 单独切换代码对比主题

- **WHEN** 用户从代码对比下拉框中选择跟随界面、GitHub Light、GitHub Dark、One Dark、Dracula 或 Nord
- **THEN** 设置页预览、提交审查和储藏详情 MUST 即时使用所选的代码背景、语法颜色、行号及增删行颜色，并保存偏好
- **AND** 固定预设在界面明暗切换后保持所选配色，跟随界面使用当前界面的原有代码配色
- **AND** 应用重启后恢复已选预设，偏好缺失或无效时使用跟随界面

#### Scenario: 切换密度

- **WHEN** 用户选择舒适或紧凑密度
- **THEN** 列表行高与间距更新并持久化
- **AND** 设置页自身仍可滚动和操作

#### Scenario: 修改旧设置

- **WHEN** 用户修改 Git 路径、默认目录、远程保护、储藏模板或时间格式
- **THEN** 对应 store 持久化，后续操作使用新值
- **AND** 非法路径/空值不会被静默当作有效

### Requirement: 应用必须下线旧工作区与旧历史视图入口

新 UI MUST 直接替换旧主界面；旧泳道、分支拓扑、文件历史、版本、提交活动、工作区文件列表、提交框和状态栏 MUST NOT 从新入口可见；应用 MUST NOT 提供手工暂存、提交框或压缩挑拣入口。

#### Scenario: 启动后只看到新主界面

- **WHEN** 应用启动
- **THEN** 只渲染新项目列表/提交列表/设置与相应弹层
- **AND** 旧 TopBar/Sidebar/CommitBox/StatusBar/旧历史视图入口不可见

#### Scenario: 冲突需要内部 add

- **WHEN** 用户在冲突弹窗标记文件已解决
- **THEN** 允许内部调用 `git_add` 标记解决，但不出现暂存区或提交框
- **AND** 继续命令由应用内部完成

### Requirement: 前端项目可以通过 build 入口执行脚本并查看日志

应用 MUST 在右下角提供「build」，点击直接打开命令弹窗。弹窗 MUST 展示当前项目根目录 package.json 的脚本、自动识别且可切换的包管理器、执行产生的实时日志，以及头部的「打开 dist」。弹窗宽约 80%、高约 86%，左侧脚本约占 1/4。项目副标题 MUST 移除「无已知差异」。

#### Scenario: 运行项目命令

- **WHEN** 用户点击一个脚本的执行按钮
- **THEN** 应用在当前项目的真实目录下通过所选包管理器执行脚本，持续显示标准输出、标准错误和运行状态
- **AND** 同项目同时只执行一个任务，状态及异常文案使用 clarification 中 Q22 的确认内容

#### Scenario: 关闭和重新打开命令弹窗

- **WHEN** 用户停止命令或关闭弹窗
- **THEN** 应用停止本次命令和子进程，退出状态与实际停止结果一致
- **AND** 当前应用会话按项目保留最近一次日志，重新打开时恢复对应记录。切换项目导致关闭时先停止原任务

#### Scenario: 打开构建产物目录

- **WHEN** 用户在 build 弹窗内点击「打开 dist」
- **THEN** 系统资源管理器打开当前项目根目录下的 dist 文件夹
- **AND** dist 文件夹不存在时入口置灰，构建结束后更新可用状态

#### Scenario: 在真实终端回答脚本问题

- **WHEN** 正在运行的脚本请求输入或展示交互菜单
- **THEN** 用户可在 xterm.js 终端直接输入文本、数字或空行，使用方向键、退格及 Ctrl+C，输入原样送入 portable-pty 中的原任务
- **AND** 彩色输出、进度覆盖和光标控制由终端解析，窗口尺寸同步给 PTY，结束或关闭过程中停止接收输入
- **AND** 选中日志时 Ctrl+C 用于复制，终端内的 Esc 交给脚本，其他关闭入口继续停止任务
- **AND** 重开或切换任务时不会重复、遗漏或混入另一任务的日志和输入

### Requirement: 异步操作必须具备 Loading、失败和防重复反馈

所有 Git 操作 MUST 在请求期间提供可见处理中状态，操作按钮防重复触发；成功 MUST 以命令结果为准；失败 MUST 保留已有有效数据并说明原因；空数据、失败和加载中不得互相混淆。

#### Scenario: 连点操作

- **WHEN** 用户连续点击拉取、推送或合并
- **THEN** 同一操作只执行一次，按钮在处理中禁用
- **AND** 完成后恢复可用

#### Scenario: 操作失败

- **WHEN** Git 命令因网络、鉴权、路径或冲突失败
- **THEN** 显示可理解的失败原因；已有提交/分支/储藏列表不被无故清空
- **AND** 用户可重试或取消

#### Scenario: 无仓库或空仓库

- **WHEN** 应用没有项目或当前仓库没有提交
- **THEN** 分别显示添加项目或空仓库说明，不显示加载失败
