## 用户操作流程

1. 启动 -> 恢复已保存项目 -> 激活上次项目 -> 加载分支/储藏/状态 -> 加载当前分支提交。
2. 项目：点击切换；右键重命名显示名；拖拽排序；项目栏保留单个添加和批量添加两个入口（用户 Q8）；批量时在系统窗口中按 Ctrl/Shift 多选文件夹；项目行操作移除。真实路径不变。取消选择不改变项目；已存在的项目跳过，单个目录失败不阻断其余目录。
3. 历史：当前分支/全部分支；搜索提交/作者/哈希；滚动到底加载更多；空/失败状态。
4. 审查：点击提交 -> 文件列表 -> 选择文件 -> diff 视图 -> 上一个/下一个 -> 复制哈希 -> 关闭回列表。
5. 分支：点击分支按钮后选择非当前分支，独立弹窗显示历史，主列表保留原范围。按 Q16/Q17，本地分支在弹窗查看上游及数量，手动获取、快进拉取和普通推送，远程分支只浏览历史。保留行内拉取和分支操作菜单，检出仍从「⋯」菜单执行。
6. 远程（用户 Q9/Q10）在分支旁常驻“↓ 拉取 N / ↑ 推送 N”，更多菜单提供手动获取与设置上游。用户点击远程操作后原位显示进度，结束刷新数量，失败时可手动重新检查。未配置上游、未检查和检查失败分别展示。更多菜单的操作文字保持单行，长上游名称可悬停查看。
7. 冲突：merge/pull/cherry-pick 返回冲突 -> 冲突条 -> 查看冲突 -> 外部编辑器打开文件 -> 标记已解决 -> 继续；残留标记拦截；中止回 normal。
8. 储藏：头部储藏 -> 新建 -> 应用/查看/删除；列表真实刷新。
9. 拣选：提交右键 Cherry-pick -> 成功刷新，冲突进入冲突条；不提供压缩挑拣。
10. 设置：主题 system/light/dark、密度、旧设置项；即时生效并持久化。

## 已确认的调整与待确认事项

已确认：

- Q1 直接替换旧 UI，旧视图/工作区/提交框下线；旧组件文件可暂留但不挂载。
- Q2 允许内部 git add / 自动 commit；不提供手工暂存/提交 UI。
- Q3 冲突由外部编辑器解决，应用内标记/继续/中止。
- Q4 移除压缩挑拣。
- Q5 新设置页保留旧版设置项（模型决定，避免 UI 替换导致能力回退）。
- Q7 补 merge continue 命令（技术必需）。

可撤回假设：

- Q6 新建储藏默认全部改动（含未跟踪），暂不做 all/staged/unstaged 范围选择；若后续需要范围选择再补。
