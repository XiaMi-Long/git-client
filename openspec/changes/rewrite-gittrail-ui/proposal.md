# 重写 GitTrail 主界面与 Git 操作

## 用户问题与业务目标

GitTrail 旧版采用三栏工作区 + 提交列表 + 状态栏布局，主界面同时承载提交、暂存、分支、远程、历史视图等大量入口，操作层级和视觉噪声偏高。用户已完成一版可交互原型，确认新的方向是：

- 左侧常驻项目列表，主区以提交历史和审查弹窗为核心；
- 项目可在软件内重命名显示别名、拖拽排序，不改真实目录；
- 分支、远程、冲突、储藏、cherry-pick 保持在提交上下文附近完成；
- 设置页独立；主题支持 system/light/dark 与密度切换；
- 本次不提供手工暂存/提交框，不提供压缩挑拣。

本次目标是把已确认原型落到真实 Tauri 2 + Vue 3 应用，直接替换旧主界面，用真实 Git 数据与命令完成日常“看历史、审查提交、管理分支/远程/冲突/储藏/拣选”的闭环。

## 用户角色、场景与操作流程

2026-11-13 对齐的前端项目工具（Q19～Q25）提供右下角「build」直达入口。弹窗展示根目录 `package.json.scripts`，采用 xterm.js 与 portable-pty 执行脚本并支持直接输入、彩色日志及交互菜单，头部的「打开 dist」进入项目根目录的构建产物目录。关闭弹窗停止任务及子进程，最近一次日志按项目保留在当前应用会话内。项目副标题已移除「无已知差异」。当前代码已接入，实际操作待人工验证。

| 处理冲突 | 冲突条 / 冲突弹窗 | 旧版冲突和暂存/提交框混在一起 | 查看冲突文件 -> 外部编辑器修改 -> 标记已解决 -> 继续；或中止 | 文件仍有冲突标记、编辑器未保存、操作已结束 | 继续前校验；失败说明原因；不丢已完成操作 |

## 功能范围与本次不涉及的内容

本次包含：

- 新应用壳、左侧项目列表、标题栏/窗口控制、主头部、提交列表、Review 弹窗、设置页、通知与操作反馈。
- 项目添加/移除、点击切换、拖拽排序、软件内显示别名及 localStorage 持久化。
- 提交列表真实数据、日期分组、搜索、分页、空态/失败态、作者与 refs 展示。
- Review 真实 diff：文件列表、统一/双栏/自动换行、词级高亮、上一个/下一个提交、复制哈希。
- 分支本地/远程列表、检出、新建、重命名、删除、合并、从远程创建、设置上游、分支拉取。
- 非当前分支独立预览（Q16/Q17）。本地分支可在弹窗查看上游、快进拉取和普通推送，远程分支只浏览历史。
- 远程 fetch/pull/push、远程分支删除和当前分支上游设置。按用户 Q9/Q10，顶栏常驻拉取与推送数量及过程反馈，远程获取由用户手动触发。
- 冲突状态条与冲突弹窗：查看冲突文件、外部编辑器打开、标记已解决、检查冲突标记、继续、中止。
- 储藏列表、新建、应用、查看、删除。
- 提交右键 Cherry-pick；冲突继续/中止。
- 旧 UI 从 App 入口下线；旧组件文件可暂留但不再挂载。
- 主题 system/light/dark、密度、设置页保留旧版现有设置项。

本次不涉及：

- 手工暂存区、文件/hunk 级暂存、提交框、提交编辑、amend。
- 压缩挑拣（Squash Pick）及其实体入口。
- 旧泳道图、分支拓扑、文件历史、版本标签、提交活动等旧历史视图。
- 标签管理、分支对比、rebase 编辑器、内置合并编辑器。
- 旧工作区文件列表和右侧 diff 常驻面板。
- 改变 Git 数据模型、远端协议或仓库目录。
- 浏览器自动化、构建、类型检查（当前环境无授权）；相关验证保持未执行或人工。

## 需求审查与澄清结论

本轮已向用户实际提出三个关键问题并获得答复：Q1 直接替换旧 UI；Q2 允许内部 add/自动 commit；Q3 外部编辑器解决冲突、应用内标记/继续。Q4 由用户本轮消息确认移除压缩挑拣。其余 Q5-Q7 为非阻塞决定或可撤回假设：保留旧设置项、储藏默认全量、补 merge continue 后端命令；均不改变用户已确认的业务边界。

未发现与现有后端契约冲突的阻塞项：分支、远程、储藏、cherry-pick、冲突标记/中止命令已存在；设置上游和 merge continue 需新增命令，属于技术补齐。原型中的 mock 数据在实现中替换为真实仓库数据。

## Capabilities

### New Capabilities

- `gittrail-ui`：新项目列表/提交历史/Review/设置主界面，以及真实分支、远程、冲突、储藏、cherry-pick 操作的行为闭环。

### Modified Capabilities

无既有主规格可修改；旧主界面行为本次整体替换。

## Impact

- 前端入口：`src/App.vue` 改为挂载新应用壳；旧 `MainView.vue`、旧 `TitleBar.vue`/`TopBar.vue`/`Sidebar.vue`/`CommitList.vue`/`FileList.vue`/`CommitBox.vue`/`StatusBar.vue` 等不再从入口挂载；旧文件可暂留但不在新 UI 可见。
- 新增前端：`src/rewrite/` 下的应用壳、项目栏、头部、提交列表、Review、设置、分支/远程/冲突/储藏/菜单/对话框组件，以及新的视觉 CSS/字体。
- 修改 stores：`repo` 增加项目别名/排序持久化与移除；`theme` 增加 system/light/dark；`settings` 保留原有设置项；复用 `commit`/`selection` 的数据与 Git 操作，但不暴露 working/commit UI。
- Tauri 后端：补齐 `git_set_upstream`、`git_merge_continue` 命令及注册；复用已有分支/远程/储藏/cherry-pick/冲突/日志/diff 命令。
- 数据：项目路径、别名、顺序存 localStorage；主题/密度/设置沿用现有 key；不修改仓库内容或 Git 对象。
- 依赖：字体资源（Archivo/IBM Plex Mono/Parisienne）需本地打包或等效离线方案；不新增网络运行时依赖。
- 风险：真实 Git 脏工作区/凭据/网络错误；大仓库 diff 性能；冲突外部编辑路径与 Tauri 权限；旧 UI 下线后的行为回退；均需静态与人工验证。

## 功能成功标准

- 打开有效仓库后，左侧项目列表出现真实项目；切换、添加、移除、拖拽排序、显示别名均可用，刷新应用后顺序和别名保留。
- 提交列表展示真实提交、作者、refs、日期分组；搜索和分页可用；空/失败状态可区分。
- 点击提交打开 Review，文件列表与真实 diff 对应；统一/双栏/换行有效；上一个/下一个提交和复制哈希可用；Esc 关闭。
- 分支浮层展示本地/远程真实分支；检出、新建、重命名、删除、合并、从远程创建、设置上游、行内拉取均调用真实命令并刷新；当前分支受保护。
- 远程 fetch/pull/push、远程分支删除、上游设置可用；失败提示真实原因，已有数据不清空。
- 冲突时出现冲突条；外部编辑器打开冲突文件；标记已解决后继续可完成 merge/cherry-pick；中止回到 normal；残留冲突标记会被拦截。
- 储藏新建/应用/查看/删除使用真实 stash 数据；新建默认收全部改动。
- 提交右键 Cherry-pick 可用；冲突可继续/中止；无压缩挑拣入口。
- 设置页主题 system/light/dark 与密度即时生效并持久化；旧版设置项仍在。
- 旧泳道/历史视图/工作区/提交框/旧设置弹窗在新入口不可见；无手工暂存/提交 UI。
- 代码静态自检无未处理 Promise/明显竞态；浏览器、构建、测试按当前授权保持未执行并明确说明。
